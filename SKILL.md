# Job Search Setup

This skill runs **once** per job search. It interviews the user, writes their profile and target-company list, and generates four skills in `<workspace root>/.claude/skills/`:

| Skill | What it does |
|---|---|
| `company-fit` | "Should I apply to X?" Researches what the company does, how it's doing and where it's heading, what it hires for, then scores it against the user's own priorities and gives a verdict. |
| `job-watch` | Checks the career pages of the user's target companies for roles that match their titles and locations, and writes new ones to a note. Runs on demand or on a schedule the user picks. |
| `job-tracker` | Keeps the application tracker current: logs applications from a job link, records anything the user did by hand (calls, referrals, rejections), scans email for replies, and says where every application stands. |
| `interview-prep` | Builds a prep pack from the job description, the company's culture and values pages and the user's own stories, then runs a mock interview, one question at a time, with feedback. |

All four read one shared data folder (default `Job-Search/`):

```
Job-Search/
  README.md         how the toolkit fits together, search criteria, target company table
  Profile.md        background + what the user wants: the yardstick for company-fit and interview-prep
  Stories.md        the user's STAR stories, built up by interview-prep
  Job-Watch.md      generated by job-watch on every run
  Applications.md   the tracker, when the user picks markdown instead of Google Sheets
  Companies/        company-fit briefs the user chose to save
  Interviews/       prep packs, mock interview scorecards, real interview debriefs
```

## Ground rules

- **Interview, don't assume.** Every specific (titles, industries, pay, locations, companies, the sheet ID) comes from the user or from a source they point you to. Write `> TODO: ...` for anything still missing rather than inventing it.
- **One question group at a time.** Use AskUserQuestion where the options are known (tracker backend, schedule, which skills to install); plain questions for free text. Play back what you heard in 2–3 lines after each group.
- **Read before asking.** If the user has a CV, LinkedIn profile, or an existing tracker, read it and draft from it instead of making them retype.
- **Show before writing.** Show the folder tree, the company list, and the matching rules, and get a yes before creating files.
- **Never overwrite.** If a target file or a skill with the same name already exists, read it and ask: replace, merge, or use another name.
- **Never send or apply.** Neither setup nor the generated skills send email, submit applications, or contact anyone. They draft, the user sends.
- **Keep this skill generic.** All user-specific values go into the generated files, never into this skill's folder.

## Step 1: Orient

1. The **workspace root** is the folder Claude Code was started in. Generated skills go in `<workspace root>/.claude/skills/`, the only place (with `~/.claude/skills/`) Claude Code discovers them.
2. If the workspace root has a `CLAUDE.md`, read it and follow its conventions (where projects live, link style, note style). If it keeps projects in a folder such as `Projects/`, suggest `Projects/Job-Search/` as the data folder; otherwise `Job-Search/`.
3. Ask whether the user already has any of this: a profile or CV summary, a list of target companies (possibly with job boards already found, e.g. an earlier `companies.json`), a tracker. Read and reuse what exists instead of rebuilding it. Imported companies with an `ats` and `slug` skip probing in Step 4.3.
4. Check which connectors are available (use ToolSearch where tools are deferred): Google Sheets, Google Drive, Gmail or Outlook, Google Calendar or Outlook Calendar, WebSearch, WebFetch. Note what's there; you'll need it in Steps 2E and 2G.
5. Ask which skills to install (default: all four), the data folder location, and the user's first name (used in the generated skills). If any of `company-fit`, `job-watch`, `job-tracker` or `interview-prep` already exists in `.claude/skills/`, say so and ask whether to replace it or install under another name (e.g. `js-job-watch`). Record the final names; the templates reference each other through `{{FIT}}`, `{{WATCH}}`, `{{TRACKER}}` and `{{PREP}}`.

## Step 2: Interview

**A. Background.** Ask for a CV (file path, Google Doc link, pasted text) or LinkedIn profile text. Read it and draft the `## Experience`, `## Strengths` and `## Gaps to watch` sections of the profile. Show the draft and ask what's wrong or missing. Gaps matter: they drive the honest cons in company-fit and the curveball questions in interview-prep.

**B. What they want.** In two or three rounds, not all at once:
- **Roles**: target titles, plus the synonyms companies use for the same job (e.g. "Data Analyst" = "BI Analyst" = "Analytics Specialist"). Seniority, and whether a step down is acceptable.
- **Industries and company type**: sectors, company stage (seed / scale-up / public / big tech / non-profit / public sector), size.
- **Location and work mode**: city or country, remote / hybrid / in-office, how many office days is acceptable, relocation, visa or right-to-work constraints.
- **Pay**: floor and target, currency, base or total (OTE, equity).
- **Priorities**: ask them to rank what matters most (pay, mission, growth and learning, title, stability, work-life balance, team and manager, work mode, brand). Company-fit scores against this ranking.
- **Trajectory**: where they want to be in 3–5 years, and what the next role must give them to get there.
- **Deal-breakers**: anything that rules a company out.
- **Timeline**: actively applying, or watching the market.

Write these into `Profile.md` from `templates/Profile.template.md`.

**C. Target companies.** This is the list job-watch checks, so it's worth doing properly.
1. Ask for any companies they already have in mind, and any to exclude (current employer, past rejections, companies they dislike).
2. Research more, using the industries, stage and location from B. Run several WebSearch queries in one turn: lists of top companies in each sector, recent funding rounds, "best places to work" lists, companies hiring for their titles in their location. Aim for 30–150 companies, depending on how niche the search is.
3. Show the proposed list grouped by segment, one line each (name, what they do, why it's on the list). Let the user cut and add. Don't proceed until they're happy with it.

**D. Matching rules.** Turn B into job-watch's `config.json` (see `references/job-watch-config.md`): title regexes, excluded titles, seniority markers, places, remote rules, Workday search terms. Show the rules in plain English ("titles containing product designer, UX designer or design lead, but not intern; located in Berlin or Germany, or remote open to Germany/EU") and check them with the `test` command (Step 4) against a few real titles the user would and wouldn't want.

**E. Tracker.** Ask where to keep it (AskUserQuestion):
- **Google Sheet**: needs the Google Sheets connector to write (Drive alone can only read). An existing sheet: get the link, read the header row, and map its columns to the standard ones in `references/tracker.md` (keep their headers; only add missing columns with their OK). A new sheet: create it with the standard header.
- **Markdown file** (`Applications.md` in the data folder): no connector needed, works offline and in scheduled cloud runs, readable in Obsidian or any editor.
If they have past applications anywhere (a spreadsheet, a list, emails), offer to import them now.
Then ask about email: if Gmail or Outlook is connected, the tracker's clean-up mode can scan for replies. If not, it works from what the user tells it.

**F. Interview prep.** Ask:
- Mock interviewer style: realistic (stays in character, feedback at the end) or coaching (feedback after every answer).
- Language of interviews, if not the language of this conversation.
- Whether to seed `Stories.md` now: offer to draft 3–6 STAR stories from the CV, with the user filling in the numbers and details. They can also skip this; interview-prep builds the bank as it goes.

**G. Schedule for job-watch.** Explain the options in `references/scheduling.md` and ask (AskUserQuestion): how often (daily, weekdays, twice a week, weekly, or manual only), and how (cloud routine, a local scheduled job on this computer, or a no-AI script-only job). Don't install anything yet.

## Step 3: Propose

Show, and wait for approval or edits:
- The data folder tree and the files to be created.
- The four skill names and one line each on what they'll do for this user.
- The company list size by segment, and how many have a job board API vs need a web check (fill this in after Step 4.3 if needed).
- The tracker choice and the schedule.

## Step 4: Create

Templates use `{{PLACEHOLDER}}` markers. Replace every one, and check that no `{{` is left in any generated file. The data templates' placeholders are named for what goes there (`{{EXPERIENCE_ROWS}}`, `{{PRIORITIES}}`, `{{COMPANY_TABLES}}` as one `### <Segment>` table per segment with Company, What they do, Board columns); the shared ones (`{{USER}}`, `{{DATA}}`, skill names) are in the table in Step 5. Fill a section with `> TODO: ...` when the user skipped it.

1. **Data folder.** Create it with `README.md`, `Profile.md`, `Stories.md`, and `Applications.md` if the tracker is markdown, from `templates/`. Create `Companies/` and `Interviews/` as empty folders (add a `.gitkeep` if the workspace is a git repo).
2. **job-watch files.** Create `<workspace root>/.claude/skills/{{WATCH}}/` with:
   - `scripts/job_watch.py`: a copy of this skill's `scripts/job_watch.py`, unchanged.
   - `config.json`: from Step 2D and 2E (see `references/job-watch-config.md`).
   - `companies.json`: `{"companies": []}` for now.
3. **Find each company's job board.** Follow `references/ats.md`. Short version: guess slugs (lowercased name, without spaces, with hyphens, plus known variants), run `python3 .claude/skills/{{WATCH}}/scripts/job_watch.py probe <slug> <slug> ...` in batches, and check that the sample titles belong to the right company. Companies with no API hit get `"ats": "web"` with their careers page URL. Write `companies.json`.
4. **Calibrate.** Run `job_watch.py fetch --dry-run`. Show the user the matches and the `title_match_wrong_location` list. Tighten or loosen `config.json` until the matches look right to them. Then fill the target company table in the data folder's `README.md` from `companies.json`.
5. **Tracker.** For a new Google Sheet, create it and write the header row. Load the `google-workspace` skill first if one is available. Write imported rows if the user gave any. For markdown, write `Applications.md` with any imported rows.

## Step 5: Generate the skills

For each skill the user chose, write `<workspace root>/.claude/skills/<name>/SKILL.md` from `templates/skills/<skill>.SKILL.md`:

| Placeholder | Value |
|---|---|
| `{{USER}}` | The user's first name |
| `{{DATA}}` | Data folder path relative to the workspace root (absolute if the skills live in `~/.claude/skills/`) |
| `{{SEARCH_SUMMARY}}` | One line: target roles, sectors, location (e.g. "senior product design roles in climate tech, Berlin or remote EU") |
| `{{FIT}}`, `{{WATCH}}`, `{{TRACKER}}`, `{{PREP}}` | The final skill names from Step 1 |
| `{{TRACKER_SPEC}}`, `{{TRACKER_READ}}`, `{{TRACKER_WRITE}}`, `{{WATCH_TRACKER_SYNC}}` | The blocks for the chosen backend in `references/tracker.md`, with the sheet ID, link and tab filled in |
| `{{EMAIL_STEP}}` | The block for the connected email tool in `references/tracker.md`, or the paste-in block |
| `{{WEB_QUERY}}` | The web-check search for job-watch: `<Company> (<3–5 title phrases, quoted, OR'd>) job <place> OR remote` |
| `{{TITLE_CRITERIA}}`, `{{LOCATION_CRITERIA}}` | The plain-English rules from Step 2D |
| `{{MOCK_STYLE}}` | `realistic` or `coaching`, from Step 2F |
| `{{LANGUAGE}}` | Interview language |

Keep each description specific to this user's search, so it triggers on their phrasing and doesn't collide with other skills.

## Step 6: Install the schedule

Follow `references/scheduling.md` for the option chosen in 2G. Show the exact command, cron line or routine config before creating it, and get a yes. Cloud routines and local scheduled jobs run without the user watching, so list the permissions they'll have.

## Step 7: Dry run and hand-off

1. Run `{{WATCH}}` once now, following the generated skill exactly. This is its first real run and fills `Job-Watch.md`. Fix anything that fails.
2. Offer to try `{{FIT}}` on one company from their list.
3. Finish with a short summary:
   - where the data folder is, and the four commands with one example each (`/company-fit Acme`, `/job-watch`, "I applied for this: <link>", `/interview-prep` before the next interview);
   - the schedule, and how to change or stop it;
   - that the profile, company list and matching rules can be changed by editing the files or by asking Claude;
   - open `> TODO:` items.

## Tips & Gotchas

- Job board APIs (Greenhouse, Lever, Ashby, SmartRecruiters, Workable, Teamtailor, Pinpoint, Workday) are public and need no key. Companies on other systems, or with custom careers sites, get a web check each run, which costs more and is less reliable. Prefer finding the API.
- Some slugs belong to a different company with the same name, and some ATSs serve demo boards for unclaimed slugs. Always check the sample titles from `probe`.
- The profile and tracker hold personal data (pay, rejections). If the workspace syncs to git or the cloud, point that out and make sure any GitHub repo is private.
- Setup can take an hour with a big company list. If the user wants to stop part-way, finish the current step, write `> TODO:` notes for the rest, and tell them to run `/job-search-setup` again to resume; on a re-run, read what exists and continue from the first incomplete step.
