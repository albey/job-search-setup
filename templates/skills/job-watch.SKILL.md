# Job Watch

Generated by `job-search-setup`. Checks every company in `companies.json` for open roles that match {{USER}}'s criteria. Results go to `{{DATA}}/Job-Watch.md`. Criteria and the company table are in `{{DATA}}/README.md`.

- **Titles:** {{TITLE_CRITERIA}}
- **Location:** {{LOCATION_CRITERIA}}

Files in this skill:
- `config.json`: title and location rules, data folder, tracker type.
- `companies.json`: company list. `ats` is the job board type (`greenhouse`, `lever`, `lever-eu`, `ashby`, `smartrecruiters`, `workable`, `teamtailor`, `pinpoint`, `comeet`, `workday`) or `web` for companies without a public job API.
- `scripts/job_watch.py`: fetcher, filter, state tracking, note renderer (Python standard library only).
- `state.json`: every matching role ever seen, with first and last seen dates. Don't edit by hand.
- `applied.json`: snapshot of the application tracker. Roles matching a tracker row go to an "In your tracker" section, never reported as new.

## Step 1: Fetch the API-backed boards

```bash
python3 .claude/skills/{{WATCH}}/scripts/job_watch.py fetch
```

Run from the workspace root. It prints JSON with `new` (roles first seen today, excluding tracked ones), `open_matches`, `errors` (boards that failed) and `web_check` (companies to check by hand in Step 2, including failed boards), and re-renders the note.

## Step 2: Web-check the `web` companies

For each company in `web_check`, run one WebSearch (in parallel batches):

`{{WEB_QUERY}}`

If the search comes back thin and the company has a `careers` URL, WebFetch it and ask for open roles matching the titles above.

Only record a role when **all** of these hold:
- The title matches the title criteria above.
- The location matches the location criteria above.
- It's a current posting with a direct URL on the company site or its job board. Don't record aggregator links (LinkedIn, Indeed) unless nothing else exists. Skip postings that look stale or closed.

Record each one:

```bash
python3 .claude/skills/{{WATCH}}/scripts/job_watch.py add --company "<name as in companies.json>" --title "<title>" --location "<location>" --url "<url>"
```

`add` prints `NEW:`, `already seen:` or `already applied (<status>):`. Only `NEW:` ones are new.

Then record how many web companies you checked:

```bash
python3 .claude/skills/{{WATCH}}/scripts/job_watch.py webdone --count <n>
```

Don't paste the whole note; link to `{{DATA}}/Job-Watch.md`. When a new role looks like a strong match, offer to run `{{FIT}}` on it.

## Maintenance

- **Add a company:** probe its job board with `python3 .claude/skills/{{WATCH}}/scripts/job_watch.py probe <slug> [<slug> ...]` (try the lowercased name, a hyphenated version, the domain). Check the sample titles belong to the right company: some slugs belong to a namesake, and some boards serve demo listings for unclaimed slugs. No hit: look at where the "Apply" links on its careers page go (Greenhouse, Lever, Ashby, Workday `<tenant>.wd<N>.myworkdayjobs.com/<site>` → slug `<tenant>.wd<N>/<tenant>/<site>`), or use `"ats": "web"` with the `careers` URL. Add the entry to `companies.json` and a row to the table in `{{DATA}}/README.md`.
- **Remove a company:** delete it from `companies.json` and the README table.
- **Change what matches:** edit `config.json` (`titles`, `exclude_titles`, `locations`), then check with `job_watch.py test "<title>" --location "<loc>" [--remote]` and `job_watch.py fetch --dry-run`. The dry run's `title_match_wrong_location` list shows what the location rules drop. Update the criteria lines at the top of this file and in the README to match.
- Boards that rate-limit (429/503) are retried with backoff, so occasional limits shouldn't show up as errors.
