## Mode 1: Log an application

Input: one or more job URLs plus "I applied" (status `Applied`) or "save this" (status `Saved`).

1. **Read the posting.** WebFetch the URL and extract the title, company, location, work mode, and any stated pay (base, total, range). Ashby pages render with JavaScript; read them from `https://api.ashbyhq.com/posting-api/job-board/<org>?includeCompensation=true` instead. If the page blocks fetching (LinkedIn often does), WebSearch the title and company to find the posting on the company's own careers page or job board. If it still can't be read, ask {{USER}} for the role and company rather than guessing.
2. **Check whether it's already there.** Match on the same link (ignoring tracking parameters such as `utm_*`, `src`, `trackingId`, `refId`), or the same company with essentially the same title.
   - **Match:** set Status to `Applied` unless it's already further along, set Date Applied to today if empty, fill empty cells from the posting.
   - **No match:** add a row: Role, Company, Date Applied = today (empty for `Saved`), Status, Pay if stated, Work Mode, Link (the company's own posting URL over a LinkedIn one), Notes only if {{USER}} mentioned a referral or similar.
3. **Confirm** in one line: company, role, pay (or "not stated"), added or updated.

## Mode 2: Update from what {{USER}} says

Input: something {{USER}} did or heard, in their own words, possibly several things at once.

1. Find the row for each company/role mentioned. If none exists (e.g. a recruiter reached out first), add one with what's known and ask for the link if there's a posting.
2. Translate to fields:
   - Recruiter or hiring manager call booked or done, next round, take-home → Status `Interviewing`, Stage to the current step, Notes: `<date> <what happened>; next: <step>`.
   - Rejection → `Rejected`, with the stage it ended at in Notes.
   - Offer → `Offer`, with the terms in Pay/Notes if given.
   - {{USER}} pulled out → `Withdrawn`, with the reason if given.

   Keep Notes short; prepend the newest event so the latest is first.
3. If an interview is coming up, offer `{{PREP}}`.
4. Confirm each change in one line.

## Mode 3: Clean-up

1. **Read** the tracker. Consider rows whose status isn't `Rejected`, `Withdrawn` or `Offer`, including rows with an empty status.
2. **Look for news.** {{EMAIL_STEP}}
3. **Classify** each item that matters:
   - Application received / thank you → no status change; note the confirmation date.
   - Rejection ("not moving forward", "other candidates") → `Rejected`.
   - Interview invite, scheduling link, recruiter call → `Interviewing`, with Stage and date.

4. **Check the data:** rows missing date or status, duplicate links, rows with only a link, inconsistent company names or date formats.

## Mode 4: Status

Read the tracker and give a short picture:
- Counts by status, and applications in the last 7 and 30 days.
- **Active processes:** every `Interviewing` row with its Stage, last update and next step, soonest first.
- **Going quiet:** `Applied` rows with no update for 14+ days.
- **Saved but not applied:** with the posting still open? (check `{{DATA}}/Job-Watch.md`).
- One line on conversion so far (applied → interview → offer), only once there are 10+ applications.

## Tips & Gotchas

- Email searches by company name miss mail from the job board's domain; search both. Search by role title too when the company name is generic.
- Rejections often come from no-reply addresses that don't name the company in the sender; check the subject and body.
- Never send, reply to, or draft emails unless {{USER}} asks. If they want a follow-up note, draft it in chat or as a draft for them to send.
